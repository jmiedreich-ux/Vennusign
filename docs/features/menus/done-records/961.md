## Design questions

- **Should a virtually-full-but-not-quite screen (e.g. Appetizers 7-9, 3 of 6 slots used) look intentionally "lighter," or is under-capacity fine as-is?** Not addressed here - #960's row-packing (sections sharing a row when they're each narrower than the grid) already applies to whatever lands on a given screen; this PR only changes which items land together, not how a partially-filled screen is styled.
- **Does the fade need a matching fade-*out* of the old content, or is fade-in alone sufficient?** Built fade-in only - the old content unmounts in the same frame regardless, but the new content easing in from transparent reads as a transition rather than a cut, which is what was asked for. A true crossfade (old content fading out while new fades in) would need to hold both in the DOM briefly and was judged unnecessary complexity for what was reported as "rough, not smooth."
