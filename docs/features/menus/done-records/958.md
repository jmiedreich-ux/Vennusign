# Done Record

- **Milestone / PR:** Every published price was $0.00, and a rotated page borrowed the wrong overflow count — PR #958
- **Head commit this record describes:** `caefd3ed0dc8f7cf2c8b7622e028462678bb84ba`
- **Author:** Claude Opus 5 on behalf of Jeremy Miedreich

**This PR exists because I reported rotation as verified against a real screen without actually looking at the screenshots I took.** I sampled section names, headings and item counts as text and called that sufficient. The owner asked me to look "with a polish eye" and pointed out I had missed the obvious: every price on the real screen read `$0.00`, and a page with one item was showing an overflow count that belonged to a different page. Both are named here rather than folded quietly into #955's record.

## Paths

| **Path** | **How it was attacked** | **Result** |
| --- | --- | --- |
| A published item's price on a real screen | Read the four rotation-watch screenshots directly (not sampled text) against the live Mana-Thai Cuisine board | **FAIL, found** — every item on every page read `$0.00` |
| The cause | Traced `DisplayController`'s section-building code; found a second, independent `decimal.TryParse(item.Price, NumberStyles.Number, ...)` that fails on the currency symbol exactly as `TRY_CONVERT` did in the already-fixed `BoardItemsSql` | **PASS** — this path feeds the *published* snapshot, which is what a real screen renders; the earlier fix only touched the *live* board query, which a deployed screen never uses |
| The fix | Added `ParsePrice`, stripping non-numeric characters before parsing, same rule as the SQL fix | **UNTESTED against a live screen at time of commit** — build succeeds locally; not yet re-verified against the deployed URL (see below) |
| A rotated page's overflow count | Read the same screenshots: "Fish" (1 item, t=21s) showed "7 more items", identical to Appetizers' overflow at t=0s | **FAIL, found** |
| The cause | Traced `PhotoGridOverflowItems` to a single computation against `displaySections` (whichever page fills the top-level `Sections` field), predating rotation; each entry in the new `Pages` array carried its full, un-sliced section list and no overflow of its own | **PASS** — confirmed by reading the code path directly, not inferred |
| The fix | Extracted `FitToScreen` as a shared local function; call it once for the top-level `Sections`/`PhotoGridOverflowItems` (unchanged behavior for a player that ignorees `Pages`) and once per entry in `Pages` | **PASS** — added `PhotoGridOverflowItems` to `DisplayMenuPageResponse` and to the player's `contentForPage`, with two new tests asserting the count switches with the page rather than sticking |
