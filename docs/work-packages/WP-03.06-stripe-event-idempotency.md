# WP-03.06 — Stripe Event Idempotency

## Status

Complete pending pull-request validation, ChatGPT review, and merge.

## Objective

Guarantee that duplicate Stripe event deliveries cannot apply a successful billing mutation more than once while keeping failed and abandoned processing retryable.

## Implemented

- Added persistent processing, processed, and failed event states.
- Added atomic event claims with `MERGE ... WITH (HOLDLOCK)`.
- Added a five-minute processing lease so abandoned claims can be reclaimed.
- Added retryable failure recording with bounded failure details.
- Added `IStripeEventIdempotencyService` for execute-once handler orchestration.
- Added dependency injection, RepoDb mapping, migration coverage, and unit tests.

## Scope Boundary

No Stripe SDK, HTTP webhook endpoint, signature verification, or subscription payload handling.

## Validation

GitHub Actions must validate restore, Release build, display production build, and unit tests. Integration-type tests are intentionally skipped under standing owner instruction.
