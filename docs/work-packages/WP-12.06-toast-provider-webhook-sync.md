## Goal

Add Toast connection configuration, provider translation, verified webhook processing, and venue-owned catalog and availability synchronization through the shared Phase 12 contracts.

## Acceptance Criteria

- Toast connection configuration is venue-scoped, and credentials remain protected at rest and absent from browser and log contracts.
- Injectable Toast gateways translate provider payloads into the existing provider-neutral catalog and webhook contracts.
- Verified Toast webhook events enter the durable queue with GUID event IDs used for replay deduplication.
- Catalog and availability changes apply only through mappings owned by the connected venue and Toast provider.
- Availability and content changes reuse `ItemAvailabilityChanged` and `ContentUpdated`.
- Venue Admin provides accurate webhook registration and status guidance without claiming live provider approval or registration.
- Focused non-integration tests cover verification, ownership, mapping, idempotency, and notifications.

## Boundaries

No polling, Clover behavior, live Toast calls, production webhook registration, credentials, Azure SQL, hosted infrastructure, containers, or cross-system integration tests.

## Validation

GitHub Actions is authoritative. All integration-type tests remain intentionally skipped.
