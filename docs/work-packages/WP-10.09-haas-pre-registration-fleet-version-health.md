# WP-10.09 — HaaS Pre-Registration and Fleet Version Health

## Status

Complete

## Goal

Provide a protected HaaS delivery workflow that can start a preconfigured TV without pairing and report actionable app-version health.

## Acceptance Criteria

- Super Admin can create a venue-scoped delivery with platform, desired version, delivery reference, and bounded expiry.
- The raw bootstrap token is returned once; only its SHA-256 hash is persisted.
- A matching unexpired token can be consumed once to launch the pre-registered display without pairing.
- Provisioning tokens are accepted only from the native wrapper bridge, never from URL query metadata.
- Heartbeats persist normalized platform and app-version metadata.
- Fleet health reports current, outdated, and unknown version states against the desired version.
- Migration 032 and focused API, repository, display, admin, and migration tests are included.

## Boundaries

No device-owner secrets, store credentials, signing material, proprietary SDK binaries, billing, POS, external services, simulator, or physical-device work.

## Validation

GitHub Actions is authoritative. Integration-type and external service/device tests are intentionally skipped.
