# WP-10.01 — Platform Launch Contract and Player Bridge

## Status

In Review

## Goal

Add one platform launch contract that lets thin TV wrappers select pairing or a persisted display target without forking the React player.

## Acceptance Criteria

- Browser routes retain their existing behavior and `web` version identity.
- Android TV, Fire TV, Tizen, and webOS are the only accepted wrapper platform identifiers.
- A TV wrapper without a saved screen starts at `/pair`.
- A wrapper with a saved screen starts at the encoded `/display/{screenId}` route.
- Platform and bounded app-version metadata flow into the existing screen registration request.
- Focused non-integration tests cover fallback, pairing, resume, encoding, and registration metadata.

## Boundaries

No native shell, persistence implementation, heartbeat version update, store packaging, signing, or integration infrastructure.

## Validation

GitHub Actions is authoritative. Integration-type tests are intentionally skipped.
