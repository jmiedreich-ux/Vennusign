## Status

Review.

## Goal

Add persisted month-over-month revenue trend data to the live Stripe revenue dashboard.

## Scope

- Persist dated USD revenue snapshots derived from the existing live Stripe source.
- Upsert at most one snapshot per UTC day.
- Return a bounded monthly trend series with deterministic percentage change.
- Add protected dashboard API and responsive trend visualization.
- Add focused non-integration tests and operating documentation.

## Acceptance Criteria

1. Snapshot values come from the established Stripe revenue aggregation.
2. Repeated capture on one UTC day is idempotent.
3. Monthly trend ordering and percentage calculations are deterministic.
4. Missing prior-month data is represented honestly rather than fabricated.
5. Required non-integration validation passes and integration tests remain skipped.

## Boundaries

No forecasting, non-USD aggregation, billing mutations, external analytics platform, or integration-test execution.

## Completion Evidence

- Added migration 011 and a UTC-date primary key for idempotent daily USD revenue snapshots.
- Captures the established live Stripe revenue aggregate after each successful protected dashboard request.
- Selects the latest daily snapshot per month and returns a bounded oldest-to-newest series.
- Calculates MRR percentage change only for an immediately preceding nonzero month; gaps and zero baselines remain `null`.
- Added a protected trend endpoint, responsive dashboard bars, focused unit tests, migration-resource coverage, and operating guidance.
- Integration-type tests remain intentionally skipped.
