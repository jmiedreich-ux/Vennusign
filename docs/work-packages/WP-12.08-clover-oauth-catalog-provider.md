## Goal

Add a claim-bound Clover v2 OAuth connection and merchant-scoped catalog import through the existing provider-neutral POS abstractions.

## Acceptance Criteria

- Venue Admin starts a Clover high-trust v2 authorization-code flow with protected, single-use, venue-and-user-bound state.
- Callback validates state, caller, redirect allowlist, returned merchant identity, and the configured Clover client before storing credentials.
- Clover access and refresh tokens plus dynamic expiry are encrypted at rest and never returned to browser contracts or logs.
- The catalog gateway accepts only documented official Clover HTTPS hosts and scopes all requests to the connected merchant.
- Categories, items, and modifiers map deterministically through `IPosProvider` and the shared idempotent catalog import service.
- Venue Admin exposes provider-neutral connection and import status plus safe connect, callback, disconnect, and import actions.
- Focused non-integration tests cover OAuth correlation/replay, host restrictions, mapping, merchant ownership, and credential-free responses.

## Boundaries

No Clover inventory webhooks, availability/price event propagation, provider conformance closure, live Clover calls, credentials, Azure SQL, hosted infrastructure, containers, or cross-system integration tests.

## Validation

GitHub Actions is authoritative. Shared authentication, dependency injection, and provider contracts require the full applicable non-integration API and data-access suites. All integration-type tests remain intentionally skipped.
