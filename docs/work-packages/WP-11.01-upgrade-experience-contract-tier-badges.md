# WP-11.01 — Upgrade Experience Contract and Tier Badges

## Status

Complete

## Goal

Create one shared, testable upgrade-experience foundation without placing upgrade prompts into product workflows.

## Acceptance Criteria

- Canonical presentation metadata exists for Starter, Restaurant Starter, Pro, and Business.
- Supported locked features map to concrete benefit copy and the minimum target tier.
- Prompt selection returns at most one opportunity in deterministic catalog order.
- Per-feature dismissal is sanitized and stored only in browser session storage.
- A reusable accessible tier badge is informational and has no action behavior.
- Focused non-integration tests cover metadata, catalog integrity, selection, dismissal, and badge semantics.

## Boundaries

No locked navigation, section previews, inline hints, sidebar rotation, upgrade modal, checkout, billing portal, Stripe network calls, or Phase 12 work.

## Validation

GitHub Actions is authoritative. Integration-type and external Stripe tests are intentionally skipped.
