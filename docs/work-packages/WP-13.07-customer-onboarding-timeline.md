# WP-13.07 — Customer Onboarding Timeline

## Status

In Progress on Sequential issue #362.

## Objective

Turn the customer/Venue Admin onboarding step indicator into the approved resumable Account, Plan, Venue, First Screen, and Go Live timeline without adding a second progress authority.

## Scope

- Timeline component derived exclusively from the authenticated onboarding snapshot.
- Complete, Current, and Upcoming text/semantics for all five ordered steps.
- Completed-count summary, current-step explanation, last-saved context, and one continue-to-current-task link.
- Horizontal connected desktop layout and coherent stacked narrow-screen layout.
- Focused Venue Admin tests and synchronized records.

## UX best-practices consultation

The dedicated UX connector remains unavailable, so W3C/WAI forms, page structure, status-message, and focus guidance was applied: use ordered logical steps, explicit headings and states, purposeful navigation, programmatic status text, and visible keyboard focus.

Sources:

- https://www.w3.org/WAI/tutorials/forms/
- https://www.w3.org/WAI/tutorials/page-structure/
- https://www.w3.org/WAI/WCAG22/Understanding/status-messages
- https://www.w3.org/WAI/WCAG22/Understanding/focus-visible

## UI/function gap analysis

- Primary goals: understand completed work, identify the current action, resume it quickly, and recognize a fully online journey.
- Hierarchy/navigation: the timeline follows the page heading and links only to the one current task below; it does not duplicate app navigation or make immutable completed steps appear editable.
- Data/actions: read snapshot progress/current step/updated time and continue to the current panel. Timeline mutation, backtracking, edit, and delete actions are not applicable.
- Essential states: signed out, loading, unavailable, partial progress, paired/offline current Go Live, and complete Online journey.
- Validation/destructive actions: none; state remains server-derived and read-only.
- Accessibility/responsiveness: ordered list, aria-current on the incomplete current step, textual Complete/Current/Upcoming state, completed-count summary, visible focus, semantic time, horizontal desktop connectors, and stacked mobile cards.
- API/data/security: existing customer-session-protected snapshot only; no new endpoint, persistence, authorization, or entitlement behavior.

## Acceptance criteria

- All five approved steps render in order and reflect the authoritative snapshot.
- One incomplete current step exposes aria-current; completed and upcoming states are textual.
- Resume summary, last-saved time, and continue link remain coherent for partial and complete journeys.
- Go Live completion remains Online-authoritative and the timeline cannot mutate state.
- Focused affected-area validation passes; integration/live-provider/device tests remain skipped.
