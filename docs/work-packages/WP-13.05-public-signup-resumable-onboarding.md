# WP-13.05 — Public Signup and Resumable Onboarding

## Status
In Progress on Sequential issue #358.

## Objective
Provide the public customer entry experience and durable onboarding state that resumes an authenticated customer through Account, Plan, Venue, First Screen, and Go Live without a configured Venue Admin token.

## Scope
- Public signup/sign-in routes in the Venue Admin web app for Google and Apple, with existing returning-user email-link and passkey paths.
- Public active tier discovery.
- Authenticated, customer-owned onboarding state with optional organization and selected tier.
- Organization creation, tier-policy trial activation, and hosted Stripe Checkout launch for paid plans.
- Server-authoritative progress that never grants entitlement from a Checkout return URL.
- Loading, empty, error, success, unauthorized, provider-unavailable, Checkout-canceled, and webhook-pending presentation.
- Migration 045, focused API/data/frontend tests, and synchronized records.

## Boundaries
Venue details and device pairing remain WP-13.06. The final customer timeline shell remains WP-13.07. Super Admin visibility, legacy-token migration, phase closure, and Phase 14+ are excluded.

## UX best-practices consultation
The dedicated UX connector was unavailable in this run, so current W3C/WAI primary guidance was consulted:
- keep forms short and split the journey into logical steps with progress;
- use explicit labels and instructions;
- identify errors in text at the affected field and summary level;
- expose asynchronous success, error, and progress messages programmatically;
- preserve visible, unobscured keyboard focus;
- support responsive layouts without hiding the current step or primary action.

## UI/function gap analysis
- Primary goals: authenticate, understand available plans, create an organization, choose trial or paid entitlement, and resume later.
- Navigation: public entry routes lead to one onboarding surface; future Venue/First Screen actions remain visible but disabled and clearly assigned to WP-13.06.
- Data/actions: read public plans and current state; create organization; select plan; start trial; launch Checkout; sign out.
- Essential states: signed out, loading, provider unavailable, validation error, API error, trial active, Checkout canceled, webhook pending, and resumed progress.
- Validation: explicit labels, required organization name, validated tier/action, server validation, text errors, and no color-only meaning.
- Accessibility/responsiveness: semantic form controls, ordered progress, status/alert regions, visible focus, keyboard operation, and single-column mobile flow.
- API/security: secure customer-session cookie, customer ownership checks, public-plan filtering, local return-path validation, allowlisted hosted Checkout URL, and webhook-authoritative entitlement.
- Destructive actions: none in this package; sign-out is reversible by signing in again.

## Acceptance criteria
- Anonymous customers can use the public entry surface and inspect public active plans.
- Authenticated customers can create/resume only their own onboarding journey.
- Trial and paid plan paths consume WP-13.04 policy and billing boundaries.
- Venue/first-screen steps are persisted/represented without implementing WP-13.06.
- Focused affected-area validation passes; integration and live-provider tests are skipped.
