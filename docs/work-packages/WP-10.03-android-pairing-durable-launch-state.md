# WP-10.03 — Android Pairing and Durable Launch State

## Status

Complete

## Goal

Connect the Android-family shell to the shared Phase 09 pairing journey and safely resume a claimed display across activity recreation and process restart.

## Acceptance Criteria

- A shell without valid durable state starts at `/pair`.
- A valid claimed display route from the trusted HTTPS player origin is normalized and stored in private preferences.
- The stored screen identifier is injected through the WP-10.01 document-start contract and selects an encoded display route after restart.
- Corrupted or non-GUID state is cleared and falls back to pairing.
- An explicit same-origin `/pair?vennuReset=1` route clears durable state and stays in the shared pairing journey.
- The native shell does not expose a general JavaScript interface.
- Focused non-integration tests cover first launch, validated persistence, restart, invalid state, and reset.

## Boundaries

No boot receiver, network/lifecycle recovery, kiosk/device-owner behavior, distribution variants, signing, store credentials, or forked player business logic.

## Validation

GitHub Actions is authoritative. Integration-type and physical-device tests are intentionally skipped.
