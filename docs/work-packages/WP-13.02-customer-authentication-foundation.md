## Goal

Add the approved passwordless Google, Apple, email-link, and customer-session foundation on top of WP-13.01 without changing legacy Venue Admin access.

## Acceptance Criteria

- Google and Apple authorization-code flows have state, nonce, PKCE, issuer/audience, verified-email, expiry, replay, and exact-return-path boundaries.
- Provider subject is authoritative; automatic email linking requires both provider verification and an already verified matching customer email, while collisions fail closed.
- Email links are random, hashed at rest, short-lived, single-use, enumeration-resistant at request time, and sent only through a delivery abstraction.
- Customer sessions use random opaque tokens, hashes at rest, secure HttpOnly SameSite cookies, absolute and idle expiry, explicit revoke, and persisted user status.
- The customer principal is derived from persisted user/session state and exposes no browser-supplied role or capability.
- Migration, repositories/services, configuration validation, dependency/auth registration, focused non-integration tests, and security/architecture records are included.
- Required GitHub Actions checks pass on the exact reviewed head.

## Boundaries

- No password login, Facebook/X provider, provider secret in source, passkey/TOTP/recovery code, trial/Stripe entitlement, onboarding UI, or legacy Venue Admin token replacement.
- No WP-13.03, Phase 14, or later work.
- Integration, live-provider/email, Azure SQL, hosted-infrastructure, container, physical-device, and cross-system tests remain skipped.

## UI Gap Analysis

Not applicable. WP-13.02 adds API authentication flows and session transport but no page or screen. Public signup/sign-in and onboarding UI remain WP-13.05.

## Implementation

- Added Google and Apple OIDC schemes with authorization code, state, nonce, PKCE, HTTPS metadata, issuer/audience/lifetime validation, provider enablement validation, and local-only return paths.
- Added provider-subject-first account resolution, verified-email creation/linking rules, active-user enforcement, and no persisted provider tokens.
- Added one-time hashed email-login tokens, enumeration-resistant requests, an environment-configured HTTPS delivery abstraction, and atomic redeem.
- Added random opaque hashed customer sessions with secure host cookies, absolute/idle expiry, throttled last-seen updates, explicit revoke, persisted-user authentication, and an isolated customer authorization policy.
- Added migration 041, repository/service/DI/RepoDb wiring, session/email/provider API contracts, focused security/unit tests, migration inventory coverage, and the customer-authentication architecture record.
