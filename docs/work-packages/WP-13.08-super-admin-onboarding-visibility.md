# WP-13.08 — Super Admin Onboarding Visibility

## Status

Complete in proposed merge state on Sequential issue #364 and PR #365.

## Objective

Give authorized Super Admin support staff a read-only view of customer onboarding progress, entitlement context, first-screen state, and last activity without creating a second progress authority or unsafe support mutation.

## Scope

- Protected support projection sourced from authoritative onboarding, organization, subscription/tier, venue, and screen data.
- Account, Plan, Venue, First Screen, and Go Live timeline with textual state.
- Organization/venue identity, plan/trial status, first-screen state, and last activity.
- Existing Super Admin route/navigation integration with refresh and copy-context actions only.
- Focused API/data/Admin tests and synchronized records.

## UI/function gap analysis

- Primary goals: locate a customer journey, understand where it stopped, see plan/trial and first-screen state, and copy safe diagnostic context.
- Hierarchy/navigation: add one support-focused route in the existing Super Admin shell; avoid duplicating customer operational navigation.
- Data/actions: read/filter support summaries, select details, refresh, and copy non-secret context. Create/edit/delete, progress changes, entitlement changes, pairing, and subscription operations are intentionally excluded.
- Essential states: loading, empty, search-no-result, partial journey, complete journey, stale activity, API error, permission denied, and refreshed/copied feedback.
- Validation/destructive actions: bounded search input only; no destructive action exists.
- Accessibility/responsiveness: labeled search, headings, ordered timeline, textual state, semantic facts/table where appropriate, status/alert feedback, visible focus, and stacked narrow layouts.
- API/data/security: existing Super Admin authorization only; server-built projection from persisted authorities; no customer-session or mutation endpoint, secrets, provider identifiers, or recovery material.

## Acceptance criteria

- Only authorized Super Admin sessions can read the support projection.
- Timeline and facts reflect authoritative persisted state without inference or mutation.
- Partial, complete, stale, empty, error, and permission states are coherent.
- Refresh/copy actions cannot modify identity, entitlement, onboarding, pairing, or subscription state.
- Focused affected-area validation passes; integration/live-provider/device tests remain skipped.
