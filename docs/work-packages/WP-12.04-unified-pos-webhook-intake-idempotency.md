## Goal

Accept verified POS webhook events into one durable provider-neutral queue and dispatch them idempotently without applying menu mutations.

## Acceptance Criteria

- `POST /api/webhooks/pos/{provider}` accepts at most 1 MiB and rejects unsupported providers, missing signatures, invalid signatures, and malformed provider metadata.
- Signature verification remains provider-specific and injectable; the first implementation uses Square's configured notification URL and HMAC-SHA256 signature.
- Verified event IDs, types, merchant identifiers, and payloads persist before the API returns `202 Accepted`.
- A unique provider/event-ID key makes replay deterministic and prevents duplicate dispatch.
- The database-backed queue atomically claims oldest work, reclaims stale processing leases, records attempts, and backs failures off for retry.
- The in-process worker dispatches through provider-neutral handlers and never logs raw payloads, signatures, or credentials.
- This package registers no menu/inventory handler and therefore performs no menu mutation.
- Focused non-integration tests cover signature tampering, metadata mapping, accepted/duplicate responses, queue persistence, stale leases, retry state, dispatch, and migration discovery.

## Boundaries

No menu, availability, quantity, or price mutation; Toast or Clover verifier; live provider call; external broker; Azure SQL integration; credentialed, hosted-infrastructure, container, or cross-system integration test is included.

## Validation

GitHub Actions is authoritative. Azure SQL, live-provider, credentialed, hosted-infrastructure, container, and cross-system integration tests are intentionally skipped.
