# WP-02.12 — Backend Notification Abstraction

## Objective

Prevent controllers and services from depending directly on SignalR infrastructure.

## In Scope

- Add `IScreenUpdateNotifier`.
- Add an implementation backed by `IHubContext<VennuHub>`.
- Support screen and venue group notifications using existing group naming conventions.
- Cover content, theme, item availability, and synchronization notifications required by Phase 02.
- Register the service through dependency injection.
- Add unit tests that verify group and event routing.

## Out of Scope

- Display client implementation
- New persistence behavior
- Phase 03 feature gating

## Acceptance Criteria

- Application code can publish Phase 02 events without directly referencing `IHubContext<VennuHub>`.
- Notifications target `screen:{screenId}` or `venue:{venueId}` correctly.
- Event names and payloads match verified client contracts.
- Unit tests cover each notifier method.

## Required Validation

- API unit tests
- Solution build
- `./scripts/validate.ps1 -SkipDisplay -SkipIntegration`

## Dependencies

Existing VennuHub scaffolding. Coordinate contracts with WP-02.10.
