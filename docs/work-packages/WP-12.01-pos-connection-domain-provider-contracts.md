## Goal

Establish the venue-scoped POS connection, protected-credential persistence boundary, and provider-neutral catalog/inventory contracts required by Square, Toast, and Clover without calling an external provider.

## Acceptance Criteria

- Supported provider and connection-status values are explicit and persist deterministically.
- One connection per venue/provider is enforced by the database and every repository read is venue-scoped.
- Plaintext access and refresh tokens pass through an injected protector before persistence and never appear in presentation contracts.
- Provider-neutral catalog and inventory contracts plus `IPosProvider` support the three approved providers without provider-specific payload types.
- DbUp migration 035, repository/service dependency registration, and focused non-integration tests are included.
- Required GitHub Actions checks pass on the exact reviewed head.

## Boundaries

No OAuth route, provider SDK or HTTP call, webhook, background processing, catalog import, menu mutation, SignalR notification, provider credentials, or Phase 13 behavior. Integration and external-provider tests remain skipped under the standing owner exception.
