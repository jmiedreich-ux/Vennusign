# WP-11.05 — Upgrade Modal and Tier Value Summary

## Status

Review

## Goal

Turn a selected feature benefit into a clear, dismissible two-step upgrade decision without starting Checkout or changing entitlements.

## Acceptance Criteria

- The sidebar CTA opens one accessible modal and hides the underlying suggestion.
- The modal identifies the locked feature, current tier, and active public target tier.
- Target-tier feature pills come from the canonical benefit catalog.
- Monthly and annual choices derive from authoritative tier pricing and the established ten-month annual rule.
- One upgrade CTA and a “Maybe later” exit are present.
- No Stripe request or entitlement mutation occurs.
- Focused non-integration tests cover content, pricing, dismissal, accessibility, and surface coordination.

## Boundaries

No Checkout session, redirect, return handling, Billing Portal, webhook change, or entitlement mutation.

## Validation

GitHub Actions is authoritative. Integration-type and external Stripe tests are intentionally skipped.
