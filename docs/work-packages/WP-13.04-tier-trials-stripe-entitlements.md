# WP-13.04 — Tier-Defined Trials and Stripe Entitlements

## Status
In Progress in Sequential issue #347 and draft PR #349 after the owner approved organization-level Stripe ownership.

## Scope
- Tier-managed no-card trial days (0–90), expiry behavior, venue limit, screen limit, public/active availability, and existing feature matrix.
- Trial creation resolves the selected tier and rejects unavailable or non-trial tiers.
- Screen creation enforces authoritative active/unexpired subscription state and tier screen capacity.
- Existing Checkout only creates a hosted Stripe session; paid activation remains webhook-authoritative.
- Organization subscription storage owns the Stripe customer/subscription, tier, trial and paid entitlement before a venue exists.
- Checkout and webhooks use organization metadata; legacy venue subscriptions remain compatibility projections/fallbacks.
- Venue creation and attachment enforce the organization tier's maximum venue count.

## Boundaries
No signup/onboarding UI (WP-13.05), simulated Stripe completion, Phase 14 work, or external integration tests.

## UI/function gap analysis
No page or screen changes. Existing tier-management API accepts the added policy fields. Public plan selection, validation/states, navigation, accessibility and responsive presentation belong to WP-13.05.

## Validation
Affected-area Actions runs #734/#735 passed the earlier tier-policy implementation. New exact-head affected-area validation is required for the organization-ownership implementation. Integration, live Stripe, Azure SQL, hosted-infrastructure and cross-system tests remain skipped.

## Approved architecture decision

Stripe customer and subscription ownership belongs to the organization. `OrganizationSubscriptions` is authoritative for linked organizations. Migration 044 backfills only unambiguous single-subscription organizations; ambiguous historical organizations remain on legacy fallback until explicitly reconciled. Organization writes synchronize legacy venue projections, while feature and capacity enforcement prefer organization state. Checkout return state never grants entitlement.

Documentation, tracker, handoff and PR status must be synchronized, then ChatGPT must review and approve the exact head before merge.
