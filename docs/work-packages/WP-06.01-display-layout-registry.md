## Goal

Define the typed board-layout contract, additive layout registry, shared display frame, and deterministic fallback behavior while preserving the existing player boot sequence.

## Scope

- Add normalized layout keys and an additive registry contract.
- Reject duplicate registrations and require a registered fallback.
- Resolve missing or unknown layout keys to the default display deterministically.
- Route ready display content through a shared frame and registered renderer.
- Add focused non-integration frontend tests.

## Acceptance Criteria

1. Layout registrations are typed and normalized consistently.
2. Registered layouts resolve directly and unknown layouts resolve to `default`.
3. Duplicate normalized keys and missing fallback registrations fail explicitly.
4. The current content fetch, heartbeat, and SignalR update sequence is unchanged.
5. Display production build and frontend tests pass in GitHub Actions.
6. Integration-type tests remain skipped and documented.

## Boundaries

No Photo Grid cards, menu payload expansion, theme persistence, scheduling, POS synchronization, or external-service validation.
