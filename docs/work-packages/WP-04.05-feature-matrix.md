# WP-04.05 — Feature Matrix

## Status

Complete pending final review and merge.

## Goal

Allow authorized Super Admin operators to review and atomically change feature access across subscription tiers with a durable audit trail.

## Scope

- Return all tiers and active features grouped by category.
- Return the current enabled state for every tier-feature cell.
- Apply a validated set of pending cell changes in one database transaction.
- Audit each effective change with the admin ID, UTC timestamp, previous value, and new value.
- Invalidate cached venue feature sets for affected tiers.
- Add a responsive matrix with dirty-cell highlighting, Enable All, Clear All, Save, and Discard actions.
- Add focused non-integration unit tests and non-integration migration validation.

## Acceptance Criteria

1. The protected API returns tiers, categorized features, current enabled cells, and recent audit records.
2. Unknown tiers/features and duplicate cell changes are rejected before persistence.
3. One bulk request applies all effective changes and their audit records in one SQL transaction.
4. Successful changes invalidate effective-feature caches for venues on affected tiers.
5. The admin UI highlights pending changes in amber and supports bulk enable, clear, save, and discard.
6. Audit records identify the admin, time, tier, feature, previous state, and new state.
7. Required restore, Release build, admin/display production builds, and unit checks pass.
8. Integration-type tests are skipped under the standing repository-owner exception.

## Boundaries

Feature creation, feature master-switch editing, tier commercial editing, venue overrides, venue tier switching, Stripe API calls, and revenue dashboard behavior are deferred.
