## Goal

Import a connected Square catalog into the existing venue menu domain through a deterministic, venue-scoped, idempotent mapping boundary.

## Acceptance Criteria

- Only an authenticated Venue Admin can start an import for the venue in their protected claim.
- Square HTTP and payload translation remain behind an injectable provider gateway.
- The server decrypts the connected venue token only for the provider call and never returns or logs it.
- One provider-owned menu plus category, variation, and modifier mappings are durable and scoped by venue and provider.
- Repeating an unchanged full import updates mapped sections/items rather than creating duplicates.
- Missing categories, stale local mappings, unsupported price data, and incomplete provider data produce deterministic conflict guidance.
- Menu sections and items use the existing Phase 5 repository and display contracts.
- Focused non-integration tests cover idempotency, conflicts, connection requirements, claim protection, mapping persistence, and migration discovery.

## Boundaries

No webhook intake, inventory or price event synchronization, live Square test, background refresh, Azure SQL integration, provider credential, hosted infrastructure, container, or cross-system integration test is included.

## Validation

GitHub Actions is authoritative. Azure SQL, live Square, credentialed, hosted-infrastructure, container, and cross-system integration tests are intentionally skipped.
