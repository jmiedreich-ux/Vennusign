# WP-04.08 — Live Stripe Revenue Snapshot

## Status

Complete pending authoritative CI, review, and merge.

## Goal

Add the current live revenue slice of the Phase 04 Super Admin dashboard with Stripe as the source of truth.

## Scope

- Query every active Stripe subscription through automatic pagination.
- Normalize monthly and annual per-unit recurring prices and quantities into USD MRR.
- Return current MRR, ARR, average revenue per active Stripe subscription, and per-tier MRR.
- Include zero-revenue configured tiers and report unmatched Stripe price IDs separately.
- Add a responsive protected-dashboard revenue panel.
- Add focused non-integration aggregation and configuration tests.
- Document protected Stripe API-key configuration.

## Acceptance Criteria

1. Revenue derives from active Stripe subscription prices rather than local tier prices.
2. Monthly and annual prices, interval counts, and quantities normalize deterministically.
3. All configured tiers appear and unmatched price IDs remain visible.
4. Stripe subscription pagination cannot truncate the snapshot.
5. Missing API configuration fails clearly without exposing credentials.
6. Required restore, Release build, frontend production builds, and unit tests pass.
7. Integration-type tests are skipped under the standing repository-owner exception.

## Decisions

- The roadmap's dollar-denominated revenue model is enforced as USD; mixed or non-USD active prices fail closed rather than producing a misleading total.
- Only Stripe `per_unit` monthly and annual recurring prices are accepted in this slice.
- Stripe.net automatic pagination is used with a 100-subscription page size.
- Current live revenue is not persisted.

## Boundaries

No month-over-month history, recent-events feed, tier switching, subscription mutation, checkout, customer portal, or integration-test execution.
