## Goal

Allow an authorized Super Admin operator to switch a venue's subscription tier while keeping Stripe and local entitlements synchronized.

## Scope

- Validate venue, current subscription, target active tier, and Stripe billing mapping.
- Update the Stripe subscription price through a testable provider abstraction.
- Persist the resulting local tier only after Stripe accepts the change.
- Invalidate effective-feature cache and record the commercial event.
- Add protected API and responsive venue-support controls.
- Add focused non-integration tests and operating documentation.

## Acceptance Criteria

1. Invalid venues, subscriptions, tiers, and Stripe mappings fail without local mutation.
2. Stripe is updated before local subscription state and failures do not create split-brain state.
3. Successful switches invalidate entitlements and record upgrade or downgrade.
4. The venue support UI refreshes its effective access after a successful switch.
5. Required non-integration validation passes and integration tests remain skipped.

## Boundaries

No checkout, customer portal, proration preview, subscription creation, cancellation, or integration-test execution.

## Completion Evidence

- Added a Stripe subscription-item updater that preserves the existing monthly or annual billing interval and applies prorations.
- Added a transactional service boundary that validates the switch, updates Stripe first, persists local tier state, records the commercial event, and invalidates entitlements.
- Added compensating local and Stripe restoration when local persistence or event recording fails.
- Added a protected Super Admin API and responsive venue-support tier controls.
- Added focused unit coverage for success, provider failure, local persistence failure, event-recording failure, and archived targets.
- Added `docs/operations/stripe-tier-switching.md`; integration-type tests remain intentionally skipped.
