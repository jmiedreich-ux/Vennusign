# WP-03.07 — Stripe Subscription Event Handling

## Status

Complete pending final CI, ChatGPT review, and merge.

## Objective

Apply the Phase 03 Stripe subscription lifecycle to venue entitlements through an idempotent, transport-neutral handler.

## Implemented

- Added a normalized Stripe subscription event contract.
- Added handlers for subscription creation, subscription updates, paid invoices, and subscription deletion.
- Resolved subscription tiers from configured monthly or annual Stripe price IDs.
- Enforced venue and Stripe subscription identity consistency.
- Updated subscription status, trial, and billing-period state.
- Invalidated feature-resolution cache entries after every applied entitlement change.
- Routed all supported events through the persistent Stripe event idempotency service.
- Added focused unit coverage for every supported lifecycle transition, duplicate deliveries, and unsupported events.

## Scope Boundary

No Stripe SDK, HTTP endpoint, signature verification, network call, checkout flow, customer portal, HaaS billing, or hosted-service integration.

## Validation

Local .NET validation is unavailable because the runtime does not contain the .NET SDK. GitHub Actions must pass restore, Release build, display production build, and unit tests against the final head. Integration-type tests are intentionally skipped under the standing owner instruction.

## Phase Result

This package completes the Phase 03 tier, feature-resolution, metering, billing-catalog, idempotency, and subscription-lifecycle roadmap slice. The next roadmap phase is Phase 04 — Super Admin CRM.
