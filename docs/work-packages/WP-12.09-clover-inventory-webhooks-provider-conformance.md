## Goal

Add verified Clover inventory events, mapped availability and price propagation, provider conformance coverage, and credential-free sync health through the existing POS abstractions.

## Acceptance Criteria

- Clover webhook intake requires the configured `X-Clover-Auth` value and validates bounded app, merchant, event type, object ID, operation, and timestamp fields.
- Inventory item events enter the existing durable queue with deterministic replay identifiers and preserve merchant/provider ownership.
- Current Clover item and stock state is fetched only through the connected merchant and official HTTPS API hosts.
- Mapped availability, quantity, and supported fixed USD price changes apply idempotently and reuse existing SignalR notifications.
- Square, Toast, and Clover adapters pass shared provider contract, cancellation, and unsupported-operation conformance tests.
- Venue Admin exposes credential-free Clover webhook registration and sync guidance without simulating external registration.

## Boundaries

No Phase 12 closure, live Clover calls, credentials, Azure SQL, hosted infrastructure, containers, or cross-system integration tests.

## Validation

GitHub Actions is authoritative. Shared webhook, provider, menu, notification, dependency-injection, and authentication changes require full applicable non-integration validation. All integration-type tests remain intentionally skipped.
