## Goal

Consume verified Square inventory and catalog events through the durable POS dispatcher, mutate only the connected venue's recorded item mappings, and reuse existing display notifications.

## Acceptance Criteria

- `inventory.count.updated` applies confirmed `IN_STOCK` quantities to recorded Square item mappings.
- Availability changes publish `ItemAvailabilityChanged`, while every quantity change also publishes `ContentUpdated` so displays do not retain a stale count.
- `catalog.version.updated` refreshes the injectable Square catalog and applies supported USD price changes.
- Repeated values produce no database write or notification.
- The provider plus external merchant connection resolves the venue before any mapping lookup, and the mapping query repeats the venue/provider boundary.
- Missing connections, disconnected connections, unsupported data, and unmapped external IDs cannot mutate menu state.
- Focused non-integration tests cover ownership, mapping scope, idempotency, availability, price, and notification selection.

## Boundaries

No polling, Toast/Clover behavior, live provider validation, operational webhook registration, Azure SQL integration, credentialed, hosted-infrastructure, container, or cross-system test is included.

## Validation

GitHub Actions is authoritative. All integration-type tests remain intentionally skipped.
