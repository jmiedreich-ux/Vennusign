# WP-02.08 — Display Application Foundation

## Objective

Prepare `src/display` for isolated, predictable development without implementing the display business flow.

## Status

Complete — reviewed in PR #7.

## In Scope

- Confirm the existing frontend framework and package configuration.
- Establish `/display/{screenId}` routing.
- Add centralized API and SignalR endpoint configuration.
- Add the SignalR client dependency if missing.
- Add a minimal application-level error boundary.
- Document independent install, build, test, and run commands.

## Out of Scope

- Fetching display content
- Rendering production layouts
- Joining SignalR groups
- SignalR event handling
- Heartbeat scheduling

## Acceptance Criteria

- The display app installs and starts independently.
- `/display/{screenId}` resolves and exposes the route value to the page component.
- API and hub base URLs are configurable without hard-coded production values.
- A top-level unexpected error produces a controlled fallback view.
- Existing backend behavior is unchanged.
