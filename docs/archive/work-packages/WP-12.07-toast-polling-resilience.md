## Goal

Add an hourly, cancellation-aware Toast stock fallback that reconciles missed webhook updates without weakening venue/provider ownership or exposing credentials.

## Acceptance Criteria

- Only connected Toast locations that are due are polled on a configurable hourly cadence.
- One process cannot overlap polling cycles; failures remain isolated per connection.
- Provider requests are throttled and all waits and calls honor cancellation.
- Bounded exponential backoff and credential-free health telemetry persist after each attempt.
- The injectable Toast stock adapter accepts only official HTTPS hosts.
- Complete snapshots apply idempotently through the same venue/provider-owned mutation service used by Toast webhooks.
- Focused non-integration tests cover translation, ownership, idempotency, overlap, isolation, backoff, cancellation, and recovery.

## Boundaries

No Clover behavior, live Toast calls, credentials, Azure SQL, hosted infrastructure, containers, or cross-system integration tests.

GitHub Actions is authoritative. All integration-type tests remain intentionally skipped.
