Start here: prepare the exact acceptance environment

  1. Open PowerShell in C:\Development\VennuSign.
  2. Start the API, Back Office and Display, and load the fixture, with one command:
powershell -ExecutionPolicy Bypass -File scripts/start-ui-test-env.ps1
  1. Wait for it to print API:, Back Office: and Display: addresses. It applies the deterministic fixture itself, so there is no separate database step.

To reset to clean fixture data at any point, stop and start it again; every start reseeds:

powershell -ExecutionPolicy Bypass -File scripts/start-ui-test-env.ps1 -Stop

Leave the window open for the entire review. Use the exact tokens shown in each sign-in case; they are configured-access tokens, not email addresses or passwords.

Previous launcher (start-track1-acceptance.ps1)

The earlier launcher opened a window per service and only printed the fixture command for you to run yourself. It also did not allow localhost as a browser origin, so the one-click sign-in below could not work with it. If you use it, apply the fixture manually:

sqlcmd -S "(localdb)\MSSQLLocalDB" -d VennuSign -E -b -I -i docs\acceptance\track-1-owner-fixture.sql

Capital -I enables QUOTED_IDENTIFIER. The fixture is idempotent, so rerunning it is safe.

Sign in without typing a token

Each button opens the Back Office in a new tab already signed in as that role. The token travels in the URL fragment, which browsers never send to a server, and is removed from the address bar before the page renders, so it reaches neither a request log nor a copied link.
